## 3. Calculate distance and clean the data

Your second code cell:


Explanation:

- First, the code calculates a distance-related value using pickup and drop-off coordinates.
- It removes rides with fare less than or equal to 0.
- It removes rides with fare equal to or greater than 100.
- It keeps passenger counts between 1 and 6.
- It removes rides whose calculated distance value is 5 or more.

Why do we clean data?

Because incorrect values and unusual records can affect Machine Learning predictions.

Technical note: Your formula is not the standard Euclidean distance formula. It calculates half the sum of squared coordinate differences. It also does not calculate real-world distance in kilometres. This is something you should correct if your project requires actual geographical distance.

## 8. Evaluate both models

Your seventh code cell:

```
def evaluate(y_true, y_pred, model_name):    rmse = np.sqrt(mean_squared_error(y_true, y_pred))    r2 = r2_score(y_true, y_pred)    print(f"{model_name} Results:")    print(f"R² Score: {r2:.4f}")    print(f"RMSE: {rmse:.4f}")
```

This function checks how well the models predict Uber fares.

Two evaluation measures are used:

1\. R² Score

- Measures how well the model explains the variation in the fare.
- A higher score is generally better.
- A score closer to 1 indicates a better fit.

2\. RMSE (Root Mean Squared Error)

- Measures the difference between actual and predicted fares.
- A lower RMSE is generally better.
- It is expressed in the same unit as the fare amount.
